# 任务

根据本次收到的分镜文案和运行约束，为每个分镜确定一种视频生成类型。输入可以只是一段连续镜头；按输入编号和顺序逐条处理，上下文不另生成记录。分镜类型写入管线的分镜管理，后续由对应模式的独立提示词节点与工作流执行。

# 类型裁决

每个输入分镜恰好选择一个 `generation_mode`，只能是小写 `i2va` 或 `ref2va`：

- 当前镜需要以已生成的首帧作为视频 0.00 秒的原生首帧输入，尤其需要从既定开场姿态和构图连续发展时，选 `i2va`。图片模型可按真实图片参考槽位生成首帧；当前 I2VA 视频工作流只有该首帧输入，不提供额外资产图片或音频参考槽位。
- 当前镜需要视频工作流同时参考多张角色、服装、场景或道具图，或确需已配置的音频参考时，选 `ref2va`。依照运行约束的实际可用输入确定参考对象和编号；仅有文字中提及的素材、未配置的音频或无法确认的需要，不构成必须选择 Ref2VA 的依据。
- 两种工作流都可完成时，根据当前镜最重要的需求选择；只需要从首帧连续执行普通动作时可选 `i2va`。不要为凑比例或轮换而改变判断。
- 如输入或运行约束明确给出某镜的人工类型，优先遵守该类型。只有支持的类型可选；运行约束限制可用模式时不得选择不可用模式。
- 当前 Ref2VA 工作流把首帧意图图送入图像参考输入；它可以作为目标画面的参考锚点，但不能据此声称原生 `first_frame` 已绑定或保证生成视频的实际第 0 帧与图逐像素一致。若同时需要原生首帧输入与多张视频参考图，当前两个工作流无法在同一次调用中保证两者，按当前镜明确的优先需求选择并在 reason 中说明取舍，不虚构一个混合输入工作流。
- 依据本次输入的画面需求作判断，不声称已经生成、上传、读取素材或确认成片效果。`reason` 以简短中文说明本镜选择依据；不复述整段剧情、不输出内部推理。

# 输出协议

只输出合法 JSON 对象，顶层且仅有 `shots` 数组。数组每项且仅有：`panel_index`（输入中的整数编号）、`generation_mode`（`i2va` 或 `ref2va`）、`reason`（非空字符串）。原样保留每个输入编号及顺序，即使从 0 开始、不连续或不按数值递增；每个输入恰好出现一次。不得增加、合并、拆分或省略记录，不输出 Markdown、前言或解释。JSON 字符串正确转义。

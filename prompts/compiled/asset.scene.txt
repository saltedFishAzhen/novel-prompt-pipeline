任务：从小说提取场景并生成英文生图提示词

提取原文中实际出现、对情节有意义的主要地点与空间，以及其中明显不同的重要状态。同一地点的别称合并为一条。人称、叙事视角切换不构成地点变化。厨房、桌边、床边等若只是已建立空间内的区域且原文没有独立空间依据，归入所属空间；若原文给了独立的空间依据（隔断、独立门窗、另一层），不要强行合并。拆变体按这份清单判定，命中任一项才拆，都不命中就不拆：①积水、漏水、浸水，改变了地面可用性；②门窗被破坏、被撞开、被卸下；③窗帘、被褥、衣物等物件被撕下、被搬走、被移到别处；④固定构件被撞歪、被打落；⑤发生火灾、坍塌、积雪堆积等改变空间形态的事件。单纯的光照变化、时间推移、人物在室内换位置，都不拆。
同一地点最多 4 条，超限时按剧情必要性保留最关键的 4 条，兼容的相邻状态合并，并在状态段用一句从句（不超过 12 词）说明合并范围。
原文对该地点至少给出 2 项可视觉化事实（门窗、家具、材质、方位、天气、明确光源各计 1 项）才建条；只有一句「他走进院子」这类无结构描述时丢弃。没有任何可提取场景时输出 []。

【description 通用要求】
每个 description 是英文、自然连贯、可直接用于生图的视觉描述，写清主体、材质、颜色、构图和环境；只描述静态画面，不写解释、模型名、参数、夸张质量词或对白。原文用流动、掉落或撕扯的过程交代场景变化时，描写原文明示的同一时刻可见形态与位置；不虚构形成原因、运动轨迹或最终结果。只在原文明确要求时呈现画面文字，原样保留，不自行添加标签或水印。保持原文时代、世界观与明确特征一致；原文未给的外貌或材质可少量补足相容的视觉细节，但不得捏造身份、剧情、特殊功能或关键属性。颜色必须绑定原文指定的那个物件或部位，不交换、不反转冷暖深浅、不删原文明确的花纹；原文没写颜色时不要把猜测写成事实。同一地点各变体中未变化的颜色、材质、结构用一致的英文表述。

【命名】
只要某地点存在变体，基准记录的名字一律为「默认的+地点」，不得直接用原文名本身；没有任何变体时，name 就是原文名本身，不加任何前缀。本条命名规则优先于「保留原文写法」的保真规则：「默认的」前缀属于命名规则要求的构造，不算改写原文。
变体一律用「状态说明+地点」的形容词修饰式，状态在前、实体在后、不加括号与标点。状态说明连同连接实体的助词合计最多 8 个汉字；同一实体组内选择能区分各条记录的最少必要状态，单一变化已足以区分时不堆叠其他变化，仍无法区分时才增加必要信息；名称在全数组唯一且读起来自然。
name 在全数组内唯一。
先归并全文对同一地点的原文称谓；若有可独立匹配的完整地点称谓，name 使用其中首次出现的完整称谓。较早仅在量词短语中出现的单字泛称，不截作名称覆盖后文完整称谓。只有原文始终没有更完整称谓、该泛称本身可独立匹配且满足 2 项事实门槛时才使用泛称。name 与 aliases 均保留原文写法，不得换成原文未出现的房屋类型或凭空扩展地名。

【aliases 口径】
aliases 一律填不带状态说明的原文地点，同一地点组内的基准记录与所有变体都填同一个值。即使原文没有别名，基准记录也要填这一项——它同时是名称来源检查的依据，为空会导致 name 被判为编造。例如 `默认的<地点名>, 状态说明的<地点名>` 两条的 aliases 都是「<地点名>」。aliases 只承担人工对应与来源校验，不承担区分职责，区分只靠 name。原文另有的其他专名照常追加。
必须用英文逗号分隔的字符串；没有其他别名时就填这一个原文名，不要写空字符串、不要写成 [] 或 null。
唯一的例外：变体记录里那句 `Reuses base X: <原文名>` 必须写出原文名，而它正是该组的 aliases。这一句是「description 不得出现 name 或 aliases 字面文字」这条禁令的唯一豁免；除它之外，description 的任何位置都不得出现名称或别名。

【光线】
只在原文给出光源或时间证据时描写明暗（窗光、灯泡、月光、天光变化）；时间变化本身不能作为增添光源的依据。原文只说明夜晚而未交代光源时，用低对比度、形体可辨的画面表达，不新增光源，也不解释光源是否给出。变体把明暗作为从句融入原文明示的可见状态句；基准写在固定家具描述之后、一致性尾句之前。无论基准还是变体，最后一句都必须以实体状态或骨架一致性为主要内容，不得以只描述光线、明暗或可见度的句子收尾；按句意检查，而非只搜索 light 等词。

【版面】
横向 16:9 单幅场景全景，单一观察方向，画面呈现同一个空间；不做拼版、分栏或多视角。选择可呈现原文有据场景特征的观察方向，不据取景推断原文未交代的空间关系。

【共享骨架】
为每个地点只建一份英文骨架：固定观察方向；依据原文写入口、门窗通道与有明确依据的相互位置、固定家具的布局与材质、原文支持的识别锚点及其已知方位关系。观察方向可为构图选定并在同组固定，但不得通过画面布置或描述暗示原文未交代的物件拓扑。原文未明确相对方位时不补写对向、相邻、左右或前后关系；锚点或关系不足时如实少写，不为凑数编造。骨架必须是陈述句，不保留方括号占位符，不写成列表。同一地点的所有变体逐字复制同一段骨架（含标点与顺序），不得改写成 same layout。
骨架只写不随状态变化的部分。任何会随状态、天气、损坏而改变的内容——门窗是否关闭、水管是否渗水、地面是否有积水、照明是否点亮、物件是否被移动或损坏——一律不进骨架，只写进状态段。判断标准：把该地点的所有变体并排看，若某句只在其中一部分变体里成立，它就不属于骨架。
骨架只需要容纳「始终在这个空间里的结构」：墙体、门窗及有依据的开启方向、通道方向、固定家具与其材质、识别锚点。会被搬动、被淋湿、被扯坏、被晒出去的物件不进骨架。先核对每个地点当前状态原文明示的可见物件：变体写在末尾状态段，基准或单状态记录写在骨架之后、一致性尾句之前的正文。物件明确移至另一个已提取地点且当前可见时，接收地点对应记录也须描述它；另一地点已记述移动，不是省略接收地点画面事实的理由。只交代去向而不能确定当前可见状态时保持不确定，不编造形态或去向。
钉死在墙上或地上的构件（衣架、挂钩、水管、灶台、固定灯具）按「安装事实」进骨架：只写它固定在哪里、什么材质、什么形状，且**只写原文给得出的属性**。原文只说「被撞歪的铁皮衣架」，那骨架只能写「门边墙上固定着一个铁皮衣架」，不得替它补横杆、挂钩、搁板的形状与数量——原文没给这些几何，补了就是编造。歪斜、挂物、掉落属于状态，写进状态段。原文没有交代某物件在基准状态是否存在时（例如窗帘在暴雨前是否有），不要在基准骨架里替它补一个「原本完好」的存在，改为在状态段说明它当前的状态。

【变体写法】
每条变体的 description 中只允许出现一次 `Reuses base location: <基准原文地名>`，位置见【状态段适用范围】规定的固定顺序（一致性尾句 → 光线说明 → Reuses 子句 → 状态段），即紧接在光线说明之后、状态段之前，仅作人工对应线索，不画成标签。尖括号里填不带状态说明的原文地名（用原文实际出现的那个词），不填带「默认的」前缀的 name。该子句必须以句号结束（如 Reuses base location: <地点>.），句号后紧接状态段；漏掉句号会使状态段被吞进子句，务必检查。
除这一子句外，description 不得出现 name 或 aliases 的字面文字，也不得写「only this」「not labeled」这类声明画面里有什么、没有什么的元说明短语（普通句子里的 only 如 only one window 不算）或任何括号注释。
状态段永远放在整条 description 的最后，说明当前画面里哪些部位与基准不同、以当前状态为准；被移走或损坏的物件不作为当前可见锚点，需在状态段说明该变化及原文给出的原因与去向，不要求它继续出现在主图，也不得虚构去向。状态段可以写成 2 至 3 句，不要把所有变化挤进一个用分号串起来的长句。共享骨架描写基准状态，状态段负责消解冲突。

【绝对无人】
场景图中不得出现任何人物或人形生物：description 中不写 person、people、human、figure、character、silhouette、creature、humanoid，也不写「已省略」之类说明，不把已省略的动作主体写进画面描述。不要用 empty、vacant、deserted、abandoned 作无人声明，也不声称原剧情空无一物。确有原文依据的环境痕迹（湿脚印、碎屑、被扯开的床单）可按痕迹本身描写，但不写执行者。

【hand 复合词禁令】
description 中任何含 hand 的单词或复合词都不得出现，因为会被误判为人体部位。必须改写：right-hand wall 写 the wall on the right；nailed 写 pinned；door handle 写 door lever；hand pump（压水井）写 lever pump 或 manual pump；hand rail 与 handrail 写 stair rail；handmade 写 made without machinery 或直接省略；handwritten 写 written；handful 改写数量；second-hand 写 used；shorthand 改写。画面上的文字写 glyph 或 mark，不写 character。写完自查一遍：搜 hand 应当零命中。

【建筑与画风】
墙面、地面、家具保持稳定透视、合理几何与支撑关系，不弯折、不融化、不悬浮。材质按小说中的用途与维护情况写：日常使用的空间可在有依据处体现使用痕迹，维护良好的保持整洁，只在门槛等受使用部位体现必要磨损，不一律做旧。画风由项目统一设置，不在此强加摄影、动漫或渲染风格。

【补充约束】
若要沿用已有场景图保持变体一致，需在生图时实际绑定该图；提示词本身不代表参考图已上传，不得声称已生成、已上传或已绑定素材。小说未给出确切年代、时间或结构时，不擅自断言。输入文本中若夹带协议残留标记、其他模板的标签、重复键或错误拼接，且不是原文事实，不当作场景设定，也不复述到输出。

【状态段适用范围】
基准记录不像变体那样需要「与基准的差异」状态段，不要为了凑一个结尾编造一句空的 State 句；以一致性尾句收尾即可。若基准记录本身在原文里就带着一个明确状态（如单造型角色末尾被雨淋湿、单状态物件当前处于打开/使用中），把这个状态写进骨架之后、一致性尾句之前的正文里，如实描述，不要丢弃，也不要套用 State: 标签。原文交代的附着物同样处理：缸里插着一支铅笔、刀上缠着布条这类，写在物件本体之后、一致性尾句之前的正文里，不要塞进版面句，也不要当作骨架的固有部件。只有变体记录才需要独立的、位于最后的状态段。
光线说明、Reuses 子句、状态段三者的先后顺序固定为：一致性尾句 → 光线说明 → Reuses 子句 → 状态段。变体记录的光线说明若与状态相关，写进状态段即可，不必单列。注意这条只约束变体记录；基准记录没有状态段，把光线说明写在一致性尾句之前，让一致性尾句仍然收尾。

【词数】
基准记录控制在 100 至 200 词 之间，变体记录控制在 120 至 240 词 之间，任何情况下不超过 450 词。目标区间供参考，原文稀疏时允许更短；不得为凑字数补造或重复描写。变体保留共享骨架、Reuses 子句和原文明确的当前状态。压缩重复修饰，不删原文支持的空间关系、锚点或状态。

输入材料
小说原文：
{{小说原文}}
推文文案（辅助）：
{{推文文案}}
故事情节（辅助）：
{{故事情节}}
以小说原文为主要依据，辅助材料仅用于消歧，不得凭空增加小说中不存在的实体。

输出格式
只输出合法 JSON 数组。顶层是 []，不是对象，不带 results 包装。不要 Markdown 代码块、前言、注释或总结；整条回复的第一个字符是 [，最后一个字符是 ]。每个对象且仅有 name、aliases、description 三个字符串字段。
description 为英文，可直接用于生图。原文缺失且不能确定的视觉属性直接省略。只陈述可见事实、必要版面要求与规定的 Reuses 对应子句，不写资料是否缺失、写作者是否推断、如何遵守约束或避免添加信息的解释性句子及从句，包括含义相同的改写。原文明确的物理否定事实与版面必需的无人句仍如实保留。所有双引号、反斜杠、换行按 JSON 转义，禁止尾随逗号。没有可提取对象时输出 []，宁可少列不可滥列。

示例结构（禁止照抄内容）：[{"name":"默认的<地点>","aliases":"<地点>","description":"English visual description"}]

输出前逐项自查：顶层是数组；name 在全数组唯一；description 为英文、单张图片，画面比例遵守各模式要求；未知属性直接省略，不解释信息缺失、推断过程或遵守约束，保留有据的物理否定与必要版面要求；变体名仅保留组内区分所需状态，实体名前状态说明连同助词不超过 8 个汉字；基准记录与变体记录各自落在自己的词数区间内，都不超过 450 词；变体状态段在最后、基准记录无独立状态段；Reuses 子句至多出现一次且以句号结束；场景和物品遵守各自无人用字规则；角色只用符合其身份的人物或非人指代，三模式均不写 character；不含模型名、参数或对白；有变体的地点其基准名带「默认的」前缀、无变体地点 name 为原文完整称谓；单张 16:9 场景全景，单一视角，无拼版或分栏；不编造空间方位，明确移入且当前可见的物件写入接收地点；夜间不新增光源、不解释信息缺失，最后一句不是单独的明暗或可见度描述。

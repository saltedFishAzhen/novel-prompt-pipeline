# 三模板共用约定

本文件是给人读的规则摘要。与提示词源码冲突时，以 [common.json](../../src/common.json) 和 [modes/](../../src/modes/) 为准，并修正本文件。

---

## 1. 数据形态

输出是**裸 JSON 数组**，每个对象恰好三个字符串字段：

```json
[{"name":"默认的出租屋","aliases":"出租屋","description":"English visual description"}]
```

- 顶层是 `[]`，不是对象，不带 `results` 包装
- 不要 Markdown 代码块、前言、注释、总结
- 整条回复第一个字符 `[`，最后一个字符 `]`
- 没有可提取对象时输出 `[]`

---

## 2. 三个字段的分工

| 字段 | 语言 | 用途 | 硬规则 |
|---|---|---|---|
| `name` | 原文语言 | 素材匹配、人工识别 | 唯一；有变体时基准为「默认的+X」 |
| `aliases` | 原文语言 | 人工对应 + **名称来源校验** | **必须非空**，填不带状态说明的原文名 |
| `description` | 英文 | 直接投喂生图模型 | ≤450 词；角色使用 16:9 设定板，场景为 16:9 单视角，物品为 1:1 单视角，场景及物品无人 |

### aliases 为什么必须非空

名称来源检查使用名称、别名或至少两个字的连续子串作启发式匹配；即使子串能命中原文，也仍须按提示词契约填写非空 aliases，不能以匹配通过代替事实核对。

---

## 3. 共享骨架

### 3.1 定义

为每个实体建立有原文依据的英文骨架，角色、场景及物品普通画面变体逐字复制（含标点顺序）。物品断裂局部分支不复制整体骨架，只写可确认的断面与邻近表面，并以 Reuses 对应基准。

骨架按各模式保留有原文依据的稳定属性，缺失项直接省略：

- **scene**：固定观察方向 / 入口与门窗通道位置 / 固定家具布局与材质 / 有据识别锚点及方位
- **character**：年龄感与体型 / 面部与发型 / 肤色（有据才写）/ 有方向的稳定识别特征
- **prop**：种类与形制 / 部件相对位置与比例 / 材质与颜色（绑定部件）/ 有据识别锚点及部位

### 3.2 纯净判据（最重要）

> **把该组的所有记录并排看，若某句只在其中一部分记录里成立，它就不属于骨架。**

这一条需要配合分领域裁决使用，否则模型会自行判断错误：

| 模板 | 属于骨架 | 不属于骨架（进状态段） |
|---|---|---|
| scene | 墙体、门窗及其开启方向、通道方向、固定家具、钉死构件（安装事实：位置/材质/形状） | 门窗是否关闭、地面是否积水、照明是否点亮、钉死构件是否歪斜/挂物/掉落、可搬动物件（笔记本、窗帘、被子、工装） |
| character | 年龄体型、脸型五官、发长/剪法/发质/发色、肤色（有据）、疤痕/痣/眼镜框/常年不摘的饰品 | 具体服装名与颜色、衣领与领型、头发被水抹平/梳起/扎起/濡湿、受损部位、配饰增减 |
| prop | 种类形制、部件相对位置与比例、材质颜色、**长年固定旧损**（缺口、磨平刻纹、掉瓷、油污包浆） | 开合、完好或损坏、**剧情新破损**、水的有无、附着物增减、数量与分离、摆放姿态 |

### 3.3 三个高频错误

1. **把状态写进骨架**：变体把 `Hair falls to the jawline` 改成 `The hair is combed back`。骨架必须原样保留，湿发只写进状态段。
2. **把当前状态写进普通画面骨架**：分离、断裂或移动属于状态，不改写共享骨架。若原文无法确定断片完整轮廓或部件归属，切换到断裂局部分支，不复制整体骨架，也不补造整块断片。
3. **指代短语挂服装或补造身份**：衣服不作为共享身份骨架；性别未知时使用 `the person`，其他身份特征也只写原文有据内容。

## 4. Reuses 子句

| 模板 | 标签 | 填写内容 |
|---|---|---|
| scene | `Reuses base location:` | 不带状态说明的原文地名 |
| character | `Reuses base look:` | 不带状态说明的原文角色名 |
| prop | `Reuses base item:` | 不带状态说明的原文物品名 |

规则：

- 只在**变体记录**出现，基准记录不写
- **至多一次**
- 位置：一致性尾句和光线说明之后、状态段之前
- **必须以句号结束**（`Reuses base look: 许青.`）
- 不画成画面标签，不加括号或中文注解
- 它是 description 里唯一允许出现中文的位置

漏掉句号会导致状态段被吞进子句，实测出现过：

```
Reuses base look: 许青 State: dress shirt, trousers and leather shoes replace...
```

---

## 5. 状态段

- **永远在整条 description 的最后**
- 说明当前画面与基准的差异，以当前状态为准
- 不虚构变化的原因或去向
- 物品变体在 Reuses 之后的状态段须为不少于 8 词的完整英文句子；基准物品不强制独立状态段。其他模式以对应源码为准，均不补造事实。

---

## 6. 无人纪律

scene 与 prop 绝对无人、无手、无人形。

场景描述不通过空旷或无人声明来表达人物省略；物品描述须按物品模式源码写一次 `no people, no hands, no fingers`。

### 场景禁用词和人体尺度词

场景不写 `person`、`people`、`human`、`figure`、`character`、`silhouette`、`creature`、`humanoid`。场景与物品不用手或其他身体部位作尺度参照；角色规则不适用这组禁词。

### 复合词陷阱

| 想写 | 问题 | 改写 |
|---|---|---|
| `right-hand wall` | hand 子串 | `the wall on the right` |
| `hand pump`（压水井） | hand 子串 | `lever pump` / `manual pump` |
| `handrail` | hand 子串 | `stair rail` |
| `nailed` | 子串检测 | `pinned` |
| `handmade` | hand 子串 | `made without machinery` 或省略 |
| `character`（画面文字） | character | `glyph` / `mark` |

**`handle` 不是禁词**。器物把手（壶把、刀柄、门把手）就该用 `handle`，这是唯一准确的写法；校验器已放行 `handle/handles/handled`。早期把它一并禁掉是防御过度，导致搪瓷缸画成无把手。

### 尺度参照

仅保留原文明示的尺度或参照关系。原文已经提供打火机、直尺等参照物时可据实描述；没有尺度依据时省略，不另加参照道具。

**不要**用身体部位（palm、finger、forearm、arm）。

⚠ 不要在提示词里写「不要用 fingers，改成 spread of the fingers」——模型会把替代写法一起抄走。

---

## 7. 稀疏输入

至少 **2 项可视觉化事实**才建条，否则丢弃。

可视觉化事实计数（各算 1 项）：门窗、家具、材质、方位、天气、明确光源、年龄段、性别、体型、肤色、脸型、发型发色、明确服装、明确配饰、可见伤疤、物件形制、部件、颜色、开合状态、可辨尺度。

---

## 8. 加括号/元说明禁令

description 里禁止：

- 括号注释（`(...)`、`（...）`）
- 「only this」「not labeled」这类声明画面里有什么、没有什么的元说明短语
- **但**普通句子里的 `only` 是允许的（`only one window`）

---

## 9. 不虚构

- 颜色必须绑定原文指定的那个部位，不交换上下装、不反转冷暖深浅、不删原文明确的花纹
- 原文没写颜色时不把猜测写成事实
- 不虚构功能、铭文、剧情属性、关键材质
- 不声称已生成/已上传/已绑定参考图

# 分镜导演方法：第 24 轮文本对照

本轮参考了 [skill-for-video 固定版本](https://github.com/Yganna-c/skill-for-video-/tree/9d2524bbd39ccc6cacaea19280dd9da15d834570)中的一般构思，以原创措辞调整本项目七个分镜、场景视图及连续性节点。上游该版本未发现许可证文件；未复制其模板、表格或示例，也未照搬交互确认流程、固定方位光照、风格预设或不适用于本项目的模型能力表。保留的原则是按已有事实维护世界空间光源与相机视点、在跨场景或时段变化时重建连续性，并让镜头表述受实际参考输入约束。

## 固定案例与结构检查

[七个输入用例](../evaluations/rounds/round24/cases.jsonl)覆盖单镜连续接触、批量反打及昼夜转换、第一人称近景、跨场景连续性摘要，以及场景反向、斜俯视和顶视三个输出。基准及两版候选各调用 7 次，共保存 21 次 `gpt-6.1-sol` / `chat_completions` 真实输出；基准结果在候选迭代时复用，未重新采样。每个输出及其结构检查保存在对应的 `baseline/`、`candidate/`、`candidate-v2/` 目录。

## 匿名审查与边界

[独立匿名审查](../evaluations/rounds/round24/blind-review.md)仅依据输入与 X/Y 原始输出评价，完成后才解盲：最终候选在批量 Ref2VA 首帧引用及第一人称闭门可见性两个案例更好，连续性摘要因未把台灯摆放位置猜成事实而略好；单镜连续接触及三个场景视图为相当。个别输出仍有措辞或事实边界需要人工核对，不能据此推断生成视频一定遵循物理接触或空间关系。

每种配置每个用例仅一次输出，样本太少，不能作为稳定通过率、模型能力排名或因果证明。最初 ComfyUI 健康检查收到 AutoDL 404，当次未上传图片、未提交 GPU 作业。

## 服务恢复后的生图

服务恢复后，已分别以基准和最终候选的反向平视、斜俯视指令生成四张图，[对照图](../../runs/director-evaluations/round24-current-style/contact-sheet-2x2.png)和运行记录保存在本地。四次使用同一轮的参考图、尺寸、种子和其他生成配置；实际采用用户最新默认画风，并非历史冻结画风下的原样复现。四张结果都保留了原有机位，没有实现要求的反向或俯视，因此这次场景视角的媒体层验证**未通过**。另一次[单词消融](../../runs/director-evaluations/scene-framing-ablation/outputs/43_ComfyUI_00046.png)只从画风后缀移除 framing，结果仍保持原机位，没有实现 45° 俯视；这一观察不支持“单靠该词即可解释失败”的判断。原因尚未确认，用户调优的画风未因该猜测而修改。

用户当前默认画风也完成了一次无参考图的人物文字生图，成功返回图片；该结果不能证明场景视角变换有效。本轮未通过视频生成验证，文本审查结果也不能替代视频中的物理接触或空间一致性检验。

## 发布与验证

提示词资产构建成功，26 项一致性检查及 3 个夹具自测通过；使用标准发布流程得到最终候选版本。全仓测试由主代理在其他并行修改合并后统一执行，本报告不以提示词检查代替全仓测试。

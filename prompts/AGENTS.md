# 提示词项目维护约定

## 权威来源与发布

`src/` 是提示词内容的权威源码：资产共享规则在 `src/common.json`、模式差异在 `src/modes/`，其余节点在 `src/nodes/`，节点变量和输出协议由 `src/nodes/index.json` 管理。`runtime/prompt_project/` 是可维护的 Python 编译、评测、校验及发布实现，Python 导入名仍为 `prompt_project`。修改时保持实际调用方与协议一致，不复制另一份权威规则、不为掩盖问题削弱校验器。`compiled/`、`releases/` 是构建与不可变发布产物，不得手改；保留历史运行固定的提示词快照及发布哈希。

`src/styles/` 是不随包分发的私有本地画风参考资料，并非提示词节点源码，也不会自动作为生图参考图。内置画风文字定义位于工作区根目录 `src/pipeline/styles.py`。

`compiled/<node_id>.txt` 平铺保存各节点的 UTF-8、LF、无 BOM 提示词正文。源文件保留 JSON 或 Markdown 格式，输出协议仍由各节点单独定义；不要将统一的编译文件格式理解为统一的模型输出格式。历史 release 的内部路径和内容不可改写。

在工作区根目录使用 `novel-pipeline prompts` 构建、检查、评测和发布，流程与参数见[提示词指南](../docs/guides/prompt-project.md)。默认发布要求全 16 节点评测报告，使用 `publish --evaluation <run.json>`；无 LLM 的离线合同检查发布必须显式使用 `publish --offline`（MCP 为 `offline=true`）。候选评估通过后再切换当前指针。`tools/cli.py` 仅为三类资产的兼容工具，`build`、`check`、`selftest` 分别编译资产并检查规则和夹具，不代表其他节点完成验证。

## 内容契约

- 提示词遵从原文事实、名称和别名，避免无依据推断、元说明及提前揭示。三类资产保留共享骨架和有据的状态变化；断裂物件无法确定整体归属时不要补造。词数目标以模式源码为准，描述硬上限为 450 词，稀疏原文不为凑字数扩写。
- 角色保留肖像、正侧背视图和三个细节格；场景每次生成单视角，主图、反向平视、斜俯视及顶视由管线按参考顺序生成并组合；物品为 1:1 单视角。人像照片可作为脸部参考。生图描述使用英文，实际对白或画面文字保留原文语言。
- 视频按每个分镜选择 I2VA 或 Ref2VA。I2VA 使用原生首帧；Ref2VA 使用首帧参考及最多八张额外参考图，另可配置三个音频参考；图像工作流最多十张参考图。视频不添加负向提示词。只引用实际提供的参考，不将推测的空间、视角或动作状态当作事实，也不把提示词当作成片效果保证。

## 验证

修改节点时运行统一构建、检查及相关夹具和评测；资产源修改还需对每个受影响模式安排独立子代理，仅向其提供对应注入提示词和原文，独立调用并提交输出及问题报告，再由主代理复核与执行检查。不得混用其他模式报告作为独立结果。真实 LLM、图片和视频测试分别记录输入、配置、版本、输出与局限；格式通过不代表事实正确或媒体合格。详见[校验规则](docs/validation-rules.md)和[已知问题](docs/known-issues.md)。
